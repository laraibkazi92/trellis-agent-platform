Tool Authorization

Read-only view of the single tool-access decision: an agent's own allowlist, plus the group rules from the workspace policy file, under one mode switch.

This page does not write anything

Group rules live in workspace/policies/tool_access.yaml in the workspace, so they are version-controlled and reviewed like any other manifest. The mode is the deployment variable {{ mode_env }}. Changes ship with the workspace: edit the file, commit it, then sync/rebuild — the sync writes the document to the registry and every enforcing process picks it up through its watch within a couple of seconds, no restart needed. There is no editor here, no policy upload and no per-surface mode switch to flip.

Scope: every tool call the framework dispatches — hub tools (use_tool), tools bound directly to an agent, edge tools and MCP servers (through the relay), and the console execute tool. The console file tools (read_file, write_file, edit_file, ls, glob, grep) do not pass through this evaluator: a rule naming one of them decides nothing, and they stay constrained by the agent's console allowlist alone. The allowlist half is always enforced; the group-rule half is what the mode relaxes.
