Tool Authorization

Default-deny boundary for tool calls. A call is allowed only when an ordered rule matches its principal, tool and scope — no match means deny. Roll out in stages: off → shadow (log would-be denials, still allow) → enforcing.

All writes apply immediately: the etcd watch invalidates the policy cache, so no restart is needed. Rolling back is the same operation — set the mode back to shadow or off.

Scope: this gate covers calls that go through use_tool (direct gateway use, and agent use_tool) and the search_tools listing. Tools bound directly to an agent are gated separately below (Bound tools), and direct hub /tools/call traffic has its own switch (Direct hub calls). Agent-driven calls resolve to agent:<name> / workflow:<name>, not the end user.

Bound tools

{% if bound_mode == 'enforcing' %}{% elif bound_mode == 'shadow' %}{% else %}{% endif %} CURRENT: {{ bound_mode }}

Tools listed in an agent's allowed_tools / allowed_mcps are registered straight onto the agent and never go through use_tool, so they have their own switch and their own rollout. Console tools, A2A delegation and admin tools are not covered. {% if bound_mode == 'enforcing' %} Enforcing — a bound tool with no matching rule returns an access-denied message to the model instead of running. {% elif bound_mode == 'shadow' %} Shadow — would-be denials are recorded below with surface=bound_tool, and the tool still runs. {% else %} Off — bound tools run without any authorization check. Direct hub calls

{% if hub_mode == 'enforcing' %}{% elif hub_mode == 'shadow' %}{% else %}{% endif %} CURRENT: {{ hub_mode }}

Every call the hub dispatches passes this switch — including traffic that already went through use_tool or a bound tool. The other two modes decide whether that surface lets a call reach the hub; this one decides whether the hub executes it, so promoting it enforces for agent traffic regardless of their state. The principal comes from the agent token the framework forwards on the call (the same token agents already use), falling back to the caller's user id and then to anonymous; an unverifiable token is not an error, it just contributes no claims. This assumes the hub port stays reachable only from the framework. {% if hub_mode == 'enforcing' %} Enforcing — a direct call with no matching rule returns an access-denied error and the tool does not run. {% elif hub_mode == 'shadow' %} Shadow — would-be denials are recorded below with surface=hub_direct, and the tool still runs. {% else %} Off — direct hub calls run without an authorization check. Default for this release. {% endif %}
